# Использование

Управление v3.0.0 выполняется через веб-интерфейс. Копируйте URL подписок и запускайте генерацию в интерфейсе; прежние команды с контейнером `node`, переменной `SUB_URL` и скриптом `rotate.js` больше не применяются.

## Ноды и домены

1. В разделе **Ноды** добавьте URL панели 3x-ui, данные авторизации, IP и флаг. IP и страна определяются автоматически, их можно исправить вручную. Основная нода используется по умолчанию.
2. При необходимости добавьте промежуточный сервер в **Relay серверы** и выберите целевую ноду. См. [Настройка перенаправления](forwarding-setup.md).
3. В **Доменах** настройте список SNI для Reality с помощью импорта, экспорта или автопоиска. Домены нод и relay добавляются автоматически при создании этих серверов; IP-адреса пропускаются.

Управляйте собственным списком доменов здесь вместо копирования `my_whitelist.txt` в контейнер или запуска прежнего скрипта `get_domains.js`.

## Создание подписки

1. Откройте **Подписки** и заполните основные данные в мастере создания.
2. В поле **ID клиента** укажите ID, email или имя существующего клиента 3x-ui либо оставьте поле пустым для автоматического создания клиента. Существующий клиент должен быть доступен на каждой выбранной ноде. Идентификатор отображается под именем подписки.
3. Добавьте инбаунды и при необходимости профили маршрутизации Happ или INCY. На подписку доступно до **20 элементов в сумме**. Маршрутизация работает в обычных и relay-подписках.
4. Для каждого инбаунда выберите ноду, relay, флаг, название, порт и тип подключения. Тип `custom` позволяет включить готовую внешнюю ссылку.
5. Сохраните подписку и запустите генерацию, затем скопируйте URL в клиентское приложение. Путь имеет вид `/bus/<UUID>` и сохраняется при ротации.

Подписки поддерживают примечания, ссылки на поддержку и сайт, статистику трафика, лимиты и сведения о сроке действия.

## Типы подключений

| Тип | Транспорт и безопасность |
| --- | --- |
| `vless-tcp-reality` | VLESS TCP + Reality |
| `vless-xhttp-reality` | VLESS XHTTP + Reality |
| `vless-xhttp-get` | VLESS XHTTP, `packet-up`, uplink GET, без TLS |
| `vless-grpc-reality` | VLESS gRPC + Reality |
| `vless-ws` | VLESS WebSocket + TLS, путь `/ws` |
| `vmess-tcp` | VMess TCP |
| `shadowsocks-tcp` | Shadowsocks TCP |
| `trojan-tcp-reality` | Trojan TCP + Reality |
| `hysteria2-udp` | Hysteria2 UDP + TLS, Salamander |
| `custom` | Готовая внешняя ссылка |

Укажите порт от `1` до `65535` или `random` для выбора из диапазона `10000–59999`. Порт должен быть доступен на ноде и relay. Стандартный скрипт перенаправления охватывает `443`, `8443` и `10000–60000`; для других фиксированных портов нужны соответствующие правила перенаправления.

Reality использует конкретный SNI или `random` из **Доменов**. Для WebSocket и Hysteria2 SNI берётся из домена или IP ноды. У WebSocket этот же адрес используется как Host; при смене адреса подключения на relay Host и SNI остаются адресом ноды. В Reality и VLESS WebSocket доступен выбор fingerprint, по умолчанию — `firefox`.

## TLS-сертификаты

WebSocket и Hysteria2 требуют файлы на соответствующей ноде:

| Адрес ноды | Сертификат по умолчанию | Приватный ключ по умолчанию |
| --- | --- | --- |
| Домен, например `example.com` | `/root/cert/example.com/fullchain.pem` | `/root/cert/example.com/privkey.pem` |
| IPv4 или IPv6 | `/root/cert/ip/fullchain.pem` | `/root/cert/ip/privkey.pem` |

При необходимости измените пути в настройках инбаунда. Приложение передаёт их в 3x-ui; файлы должны уже существовать на этой ноде.

## Генерация и Журнал

Включите авторотацию у нужных подписок и задайте общий интервал от **10 минут**. Для стабильности рекомендуется ежедневная ротация (1440 минут) и ежечасное обновление подписки в клиенте. Ручная генерация доступна для одной подписки или всех активных подписок с включённой авторотацией.

Генерация, удаление подписок и нод, удаление relay, установка и удаление перенаправления выполняются в фоне. Следите за прогрессом и результатами в **Журнале**. При временных ошибках создания и удаления инбаундов выполняется до трёх попыток; ошибка одной подписки не останавливает пакет. Новые инбаунды подготавливаются до удаления старых, а при неудачной замене рабочие подключения сохраняются.

Журнал обновляется автоматически, поддерживает фильтры по процессу и статусу, показывает по 20 записей на странице. Завершённые записи хранятся до 30 дней с ограничением в 50 000 событий.

Очередь сохраняется после перезапуска приложения. Задача, выполнявшаяся при остановке, помечается как прерванная и не перезапускается автоматически. Перед повторным запуском проверьте Журнал и состояние ноды.
